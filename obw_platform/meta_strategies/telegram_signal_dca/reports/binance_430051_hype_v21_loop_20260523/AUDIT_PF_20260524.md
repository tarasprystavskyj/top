## Likely Issues / Caveats

1. `max_dd_pct` is misleadingly small.
   The summarizer default is `initial_equity=10000`, while each trade is `target_notional=100`. For the same PnL stream:
   - initial equity `10000`: net `1.5741%`, maxDD `-0.020956%`
   - initial equity `1000`: net `15.7409%`, maxDD `-0.208840%`
   - initial equity `100`: net `157.4090%`, maxDD `-2.018916%`

2. Open positions are excluded from historical PF until closed.
   The current open-position endpoint had an active HYPE long. At one probe it was slightly negative. This does not enter `dca3_trades.csv` because that file is based on closed position history.

3. Closed-history sample is unusually clean.
   The source lead closed-history PF is already about `33.16`, so a strategy PF around `36.67` is plausible for this specific closed sample, but it should not be treated as robust proof without forward paper-live and rolling-window checks.

4. Execution model is simplified.
   DCA fill levels are simulated from 1m high/low touches, with static fee/slippage drag. No order book fill probability, partial fill, latency, or market impact model is applied.
