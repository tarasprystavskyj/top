top_1: людський вхід у проект

Це коротка стартова сторінка для людей. Деталі можна питати в агентів, але базові межі відповідальності й правила роботи варто прочитати тут.

Хто за що відповідає

  • Тарас — CTO і тімлід. Відповідає за технічний напрям, research, live-readiness, merge-рішення.
  • Тетяна — frontend/design напрям. Має PM/HR досвід і технічну освіту.
  • Агенти — Codex Pro CLI, Gemini 3 free, Claude CLI. Вони роблять більшість реалізації, але відповідальність лишається за людиною-власником задачі.

Гілки

  • ui-admin — UI, frontend/design, backend API для UI.
  • akela-meta-short-worker — Akela, V21, тюнери, backtests, data/research.
  • main — стабільна база, не scratch-гілка.

Що читати

  • TEAM.md — люди, ролі, ownership, як підписувати коміти.
  • continuity/AGENT_RULES.md — правила для агентів.
  • continuity/AGENTS.md — загальні continuity-правила.
  • continuity/MAP.md — карта напрямків проекту.
  • continuity/lines/ui-admin.md — UI-напрям.
  • continuity/lines/strategy-research.md — research/стратегії.
  • continuity/lines/backtest-integrity.md — довіра до backtest/paper/live.

Мінімальний workflow

  • Перед роботою: git status -sb.
  • Перевірити, що гілка правильна.
  • Перед ризиковою роботою агента зробити commit або backup branch.
  • Комітити стабільні маленькі checkpoints.
  • Push після стабільного checkpoint.
  • Не комітити .env, DB/, _reports/, _handoff/, runs/.

Як підписувати agent-assisted commit

Human: Taras <role: CTO/team lead>
Agent: Codex CLI <resume/session: ...>

Якщо людина не впевнена, правильна дія — попросити агента пояснити поточну гілку, список файлів, ризики і найменший безпечний наступний крок.
